# Package activation

Reference `PinguApps.BlazorContentContracts` in a component library. Its NuGet dependency on `PinguApps.BlazorContentContracts.Analyzers` carries `include="All"`; the analyzer package contains no runtime assembly or Roslyn dependencies. The annotation assembly also contains the compiled contract schema, so no separate metadata package is needed.

The analyzer package imports its targets through `buildTransitive`. These targets add the selected package analyzer and Razor additional sources, and publish inferred compiled summaries. This works through Application → WrapperLibrary → ComponentLibrary package dependencies and project references. A direct analyzer reference is optional. NuGet selects one version per package ID; the target removes existing copies of this analyzer before adding that selected version once. A direct higher version follows normal NuGet direct-dependency resolution; downgrades remain NuGet warnings/errors rather than silently loading two versions.

Library authors should retain the annotation dependency with its default assets. `PrivateAssets="all"` prevents the dependency from flowing to consumers, and therefore prevents automatic downstream activation and availability of annotation/schema types. Use that only when deliberately isolating the dependency. An explicit analyzer reference with `PrivateAssets="all"` checks the current library but does not replace the flowing annotation dependency. Do not exclude `buildTransitive` when automatic downstream activation is wanted. `IncludeAssets` is an allow-list: omitting `buildTransitive` removes the transitive setup, and omitting `analyzers` removes NuGet's direct analyzer discovery. Excluding only `analyzers` does not disable the explicit buildTransitive activation target.

Set `<BlazorContentContractsEnabled>false</BlazorContentContractsEnabled>` in a consumer project (or Directory.Build.props) to disable this package's analyzer, Razor source registration and summary publication in that project. This removes both direct NuGet discovery and transitive activation. Standard `RunAnalyzers=false`, `RunAnalyzersDuringBuild=false` and diagnostic severity configuration remain controlled by the compiler/MSBuild. `BlazorContentContractsPublishSummaries=false` disables only inferred summary publication; explicit contracts remain available.

The Gherkin package activation scenarios restore exact local nupkgs into isolated caches and build direct, two-library package, project-reference, central-package-management and net10.0/net11.0 multi-target consumers. They assert a real Razor BCC005 diagnostic, exactly one selected analyzer, and explicit opt-out/private dependency behaviour. The verification script additionally inspects nupkg metadata/layout and runs an independent consumer whose runtime dependency list excludes analyzer and compiler binaries. Compiled-library scenarios separately verify the contract schema and summaries from real packages.
